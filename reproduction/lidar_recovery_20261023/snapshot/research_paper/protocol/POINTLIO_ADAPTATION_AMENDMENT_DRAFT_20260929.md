# Draft R2 amendment: Point-LIO development indicator adapter

**Status:** Proposed; not approved, implemented, or frozen. An independent
protocol review is required before coding the adapter or running the 32-pair
Point-LIO development replication. No Point-LIO health output, threshold or
replication result has been generated by this proposal.

## Why an amendment is needed

The fifth R3 review found that Point-LIO's existing T15 smoke proves only the
pose output contract. The pinned source exposes its own accepted
point-to-plane measurement Jacobian, but it applies point-time-group updates
inside each LiDAR frame. Making a scan-rate health signal therefore requires
an explicit rule for pooling those groups, placing each rotational Jacobian in
a common basis, deciding validity for partially measured frames, and selecting
a separate Point-LIO threshold on development data. The existing R2
specification only defines the FAST-LIO `G_3m` threshold; it does not authorize
fitting a Point-LIO threshold. This amendment leaves the recovery labels,
time-grid, splits, sample count and held-out IDs unchanged.

## Pinned-source evidence

- Point-LIO is pinned to commit
  `4b86a469eb5572e70ed575af25b5f15dd06e8e3c` from
  [`hku-mars/Point-LIO`](https://github.com/hku-mars/Point-LIO).
- `src/Estimator.cpp`, `h_model_output` (lines 218–321), selects map matches,
  fits planes and fills the first six `h_x` columns. With the frozen T15
  configuration (`use_imu_as_input=0`, `extrinsic_est_en=false`), the row is
  `[n_W^T, (p_B × R_g^T n_W)^T]`; six additional extrinsic columns are zero.
  An independent read-only source audit reports that a finite-difference check
  confirmed the first six columns' order, sign and basis against T08 for this
  fixed-extrinsic configuration.
- The same function selects rows after the pinned five-neighbor plane fit and
  the `p_norm > match_s * pd2^2` gate. These are Point-LIO's own accepted
  correspondences, not FAST-LIO's rows and not a shared-row DCReg comparison.
- `include/IKFoM/IKFoM_toolkit/esekfom/esekfom.hpp` sets
  `maximum_iter=1` in the pinned dynamic-update initialization (lines 107–130).
  Each point-time group therefore contributes one pre-update linearization.
  The state changes between groups, while Point-LIO inserts map points after
  the frame (`laserMapping.cpp`, around lines 1010–1016).
- The T15 configuration sets `lidar_meas_cov=0.01`. Pinned IKFoM uses
  `M_Noise` additively in the innovation covariance when group rows are fewer
  than 30, but multiplies `J^T J` by it in the larger-group branch. Therefore
  `0.01` is not a uniformly interpretable inverse-noise weight. This proposal
  does not call the exported geometric score a posterior or a faithful native
  covariance estimate.
- With `publish_odometry_without_downsample=false`, Point-LIO timestamps its
  published pose at `lidar_end_time` (`laserMapping.cpp`, around lines
  271–282). The current simulator configuration uses this 10 Hz output.

## Proposed Point-LIO scan-rate measurement

For each current LiDAR frame, group accepted Jacobian rows by Point-LIO's
existing point-time updates. Each group `g` has

```text
J_g = [ J_translation,g  J_rotation,g ]
J_translation,g = n_W^T
J_rotation,world,g = J_rotation,g R_g^T
J_g,common = [ J_translation,g  J_rotation,world,g ]
H_frame = sum_g J_g,common^T J_g,common
N_frame = total number of accepted rows across included groups
```

`R_g` is the Point-LIO body-to-world rotation at that group. The multiplication
by `R_g^T` transports each right/body-tangent rotational Jacobian into the
single world tangent basis before pooling; otherwise the frame sum would mix
different rotation bases. Since the state evolves as point groups are
processed, this is explicitly a **frame-pooled measurement-geometry
adaptation**, not one scan-level state estimate or a byte-for-byte T08
linearization.

Emit one diagnostic record after all current-frame point groups finish, at
`lidar_end_time`. This gives one 10 Hz record on the common evaluation time
grid. Record `N_frame`, total/valid/empty group counts, `segment_id`, timestamp,
source stage, validity and unavailable reason, in addition to the 6×6 raw
`H_frame`.

### Proposed scores

Let `S = diag(1,1,1,1/3,1/3,1/3)` use the frozen 3 m lever scale. The primary
continuous geometric score uses the common T08 normalization:

```text
G_PointLIO,3m = S H_frame S / (N_frame * 0.001)
FASTLIO_MIN_EIG_G3_PointLIO = smallest_eigenvalue(G_PointLIO,3m)
```

The common `0.001` preserves the same declared score scale as T08 and does not
change Point-LIO's `lidar_meas_cov=0.01` setting. It is a measurement-only
geometry score, not an assertion that the two EKFs use the same noise model.
The Point-LIO decision threshold is selected separately on development data
using the R2 development-only selection rule and is frozen before any
held-out input. It is never copied from FAST-LIO.

For the second indicator, pass the **raw** `H_frame` and `N_frame` to the
existing DCReg Schur detector, retaining its frozen permutation,
pseudoinverse/PSD tolerances, `N>=6` requirement and strict `kappa > 10`
direction flags. The Schur ratios are invariant to a common positive scalar.
This is a DCReg detector adaptation on Point-LIO's own accepted rows, not
shared-correspondence parity or the full DCReg registration system.

## Proposed availability and reset rules

- An empty input frame yields `UNAVAILABLE / EMPTY_FRAME`.
- Point-time groups with no accepted correspondences contribute no rows and no
  Hessian entries; they are counted as empty/unavailable groups, never inserted
  as zero rows. A frame is `VALID` only when `N_frame >= 6` and the aggregate
  matrix is finite and numerically valid.
- A frame with `N_frame < 6` yields `UNAVAILABLE /
  INSUFFICIENT_CORRESPONDENCES`. The actual count and group counts remain
  recorded.
- Any non-finite row/matrix or materially non-PSD result makes the **whole
  frame** `UNAVAILABLE / INDICATOR_NUMERIC_FAILURE`; do not emit a partial
  “healthy” score from corrupted values.
- If a reset occurs in a frame, mark that frame unavailable, advance the
  segment, and do not pool across the reset. No interpolation crosses a
  segment boundary.
- The evaluation continues to use the R2 common 10 Hz tick grid and latest
  diagnostic no older than 0.2 s in the same segment. The frame record is
  timestamped at `lidar_end_time`; point-group sub-times remain in the
  diagnostic sidecar for audit.

The independent reviewer must confirm or revise these partial-group, empty
frame, reset and numerical-failure rules before implementation.

## Required acceptance before replication

1. Independent review approves or revises this amendment and determines its
   effect on the R2 measurement contract. No full development replication
   starts until the amendment is accepted and hash-recorded.
2. Add analytic tests for known Jacobian rows, tangent transport, frame
   aggregation, 3 m scaling and DCReg parity. Verify singular, insufficient,
   partial-group and reset behavior is explicitly unavailable as specified.
3. Build a development-only sidecar that leaves Point-LIO state updates
   unchanged. Compare sidecar-on/off pose output byte-for-byte on the retained
   seed-14 input; check timestamps against `lidar_end_time`, flush counts,
   source hashes and all output identities.
4. Run the predeclared 32 development corridor/control pairs only after
   acceptance. Use the R2 selection rule for a separate Point-LIO threshold;
   include every failed or unavailable run. Freeze the Point-LIO adapter,
   environment, threshold and input/output hashes in a separately reviewed
   development freeze before held-out exposure.

No held-out input, geometry screen, threshold tuning or replication result was
used to draft this proposal.
