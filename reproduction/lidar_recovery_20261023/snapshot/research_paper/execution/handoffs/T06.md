## Unresolved limitations and next task

FAST-LIO documents `extrinsic_T/R` as the LiDAR pose in the IMU frame. GEODE publishes a `T_IMU_LiDAR` matrix but does not define its direction; the camera/IMU/LiDAR matrix cycle does not resolve it. The user indicated they could not adjudicate this technical convention, so the published matrix was used directly for an explicitly provisional replay. The released reference trajectory also lacks a precise body-frame convention, covariance and fix status. Consequently, formal pose-error and recovery results remain unverified.

T07 is next for an offline evaluator with independent fixtures and explicit unavailable reasons. It should audit whether GEODE's reference can be converted to the FAST-LIO body. If not, its development replay errors must remain unavailable and R1 must consider a supported candidate change. A concrete option already in the plan is to move up the pinned Point-LIO smoke task (T15) on the same retained development sequence, while keeping FAST-LIO2's failed runs as a baseline; that changes the primary-backend order and requires scientific review. A different dataset with explicitly matched body frames and a weak-to-rich transition is the alternative. Neither replacement has been made quietly.
